# SomaliStream — self-host + Somali + white-label runbook

This documents the **SomaliStream** deployment of Aliran: a real, self-hosted panel +
broadcaster, with a Somali (`so`) locale and a white-label brand. Every command here was
run and verified end to end on this checkout. The proof is in
[Verification](#verification) below.

## 1. Layout

```
brands/
  gen-art.py                 regenerates the brand PNGs (needs Pillow)
  somalistream/
    service.json             brand descriptor (panelPubKey, name, colors, defaultLocale)
    icon.png  logo.png  wallpaper.png  banner.png
i18n/locales/so.json         Somali catalog — 377 keys, 1:1 with en.json
```

The brand descriptor is baked into branded builds by `tools/brand.mjs`. It carries only
public data: the panel **public** key, a display name, colors, and the start locale. There
is deliberately **no `dev` credentials block** — `brand.mjs` refuses one.

## 2. Build the images

```bash
docker compose build
```

Builds two images from the repo root context: `project-panel` and `project-broadcaster`.
The broadcaster image carries **ffmpeg**, which is what makes the `test` source and every
push/pull source work.

## 3. First-time panel setup (once)

`init` writes the panel keypair and prints the public key + pairing code. `add-admin`
reads the password from stdin — never from argv.

```bash
docker compose run --rm panel node src/admin-cli.js init
printf '%s\n' "$PANEL_ADMIN_PW" | docker compose run -T --rm panel node src/admin-cli.js add-admin admin
```

Then create the broadcaster's local control admin (separate dashboard, separate credentials):

```bash
printf '%s\n' "$BROADCASTER_ADMIN_PW" | docker compose run -T --rm broadcaster node src/control-cli.js add-admin admin
```

## 4. Configure the two services

`panel/.env` — the operator-facing service name is what the dashboards and pairing screens
show. This is the white-label lever on the server side:

```
SERVICE_NAME=SomaliStream
ADMIN_ENABLED=1
```

`broadcaster/.env` — point the broadcaster at the panel and register its feed:

```
PANEL_PUBKEY=9566593cea7cf637b8c3e63b0e640d02aaa1c3f2ea99ac33c414131fba2bf0e7
PUBLISHER_KEY=<from `docker compose run --rm panel node src/admin-cli.js add-publisher`>
CONTROL_ENABLED=1
STREAM_ID=demo
TITLE=SomaliStream Demo
CATEGORY=General
INPUT=test
```

`INPUT=test` is the self-contained ffmpeg source (colour bars + tone). Replace it with a
`push`, `pull`, or `file` source for real programming; see `docs/reference.md`.

## 5. Run it

```bash
docker compose up -d
curl -s localhost:3210/healthz   # {"up":true,...}
curl -s localhost:3310/healthz   # {"up":true,...}
```

Both services use `network_mode: host`, so the dashboards stay on `127.0.0.1` and
Hyperswarm hole-punching is not double-NATed. Reach the dashboards from your laptop over an
SSH tunnel or a reverse proxy (`deploy/Caddyfile.example`).

### 5b. This deployment — dashboards published on the runtime ingress

This instance is deployed on an Agent Canvas runtime that publishes two HTTPS hosts
straight to the sandbox, so the dashboards are reachable without an SSH tunnel. The panel
admin and broadcaster control were re-bound off loopback to the ingress ports:

| Surface | `.env` change | Local | Public |
|---|---|---|---|
| Panel admin | `panel/.env`: `ADMIN_HOST=0.0.0.0`, `ADMIN_PORT=12000` | `http://127.0.0.1:12000` | https://work-1-cokjyqzwfcnoxhzu.prod-runtime.all-hands.dev/ |
| Broadcaster control | `broadcaster/.env`: `CONTROL_HOST=0.0.0.0`, `CONTROL_PORT=12001` | `http://127.0.0.1:12001` | https://work-2-cokjyqzwfcnoxhzu.prod-runtime.all-hands.dev/ |

Original `.env` files are preserved as `.env.bak-deploy`. On a real VPS keep the dashboards
on loopback and front them with Caddy — the API speaks plain HTTP and carries a bearer token.

```bash
# Apply the ingress bindings (already done here) and recreate the containers:
docker compose up -d
```

Admin logins (rotate before any real launch — see §9):

```bash
# Panel admin:   admin / SomaliStream-Admin-2026!
# Control admin: admin / SomaliStream-Control-2026!
# Demo viewer:   alice / SomaliStream-Viewer-2026!   (entitled to `demo`)
curl -s -X POST localhost:12000/api/login -H 'content-type: application/json' \
     -d '{"username":"admin","password":"SomaliStream-Admin-2026!"}' | jq -r .token
```

Verified end to end: both dashboards sign in and render, the panel `/api/status` reports
`serviceName: SomaliStream` with 1 live stream, and a real viewer played `demo` over the
public DHT (`RESULT: PASS ✅`).

The broadcaster registers its feed with the panel over the DHT at boot — the stream appears
in the panel catalog by itself, with `isLive: true` once the first segment lands.

## 6. Create a viewer and grant the channel

While the panel runs, use its HTTP API (the on-disk DB is locked by the running process):

```bash
PT=$(curl -s -X POST localhost:3210/api/login -H 'content-type: application/json' \
     -d '{"username":"admin","password":"'"$PANEL_ADMIN_PW"'"}' | jq -r .token)

curl -s -X POST localhost:3210/api/users -H "Authorization: Bearer $PT" \
     -H 'content-type: application/json' \
     -d '{"username":"alice","password":"'"$VIEWER_PW"'"}'

curl -s -X POST localhost:3210/api/users/alice/grants -H "Authorization: Bearer $PT" \
     -H 'content-type: application/json' -d '{"streamId":"demo"}'
```

## 7. Build the branded app

The Android/desktop app is built from `client/`. A brand build swaps in the descriptor and
generates the Android resource overlay:

```bash
node tools/brand.mjs somalistream            # validate + build APK
node tools/brand.mjs somalistream --no-build  # validate + res overlay only
```

`--no-build` needs no Android SDK and proves the brand is well-formed: it writes
`client/android/app/build/aliranBrand/somalistream/res/` with the app name, adaptive
launcher icon, logo, wallpaper, and TV banner. A full APK build needs Java + the Android
SDK (not installed on this box — see [Not done here](#not-done-here)).

Point the desktop app at this panel by copying the descriptor:

```bash
cp client/brands/somalistream/service.json desktop/config/service.json
```

## 8. Somali localization

`i18n/locales/so.json` is a full 377-key Somali catalog with all `{placeholders}` and
plural forms preserved. It is registered in `i18n/src/index.ts` (SUPPORTED_LOCALES,
PLURAL_FORMS `so: ['one','other']`, CATALOGS) and mirrored into the two runtime boundary
duplicates (`client/backend/backend.mjs` LANGUAGES, and the `so`/`som` rows in
`client/src/lang.ts` and `desktop/renderer/src/lang.ts`). The brand descriptor sets
`defaultLocale: "so"`, so a device whose language is not one of the 15 ships starts in
Somali; a viewer's own device language and their Settings choice both still win.

Guard:

```bash
node tools/i18n-test.mjs   # RESULT: PASS (15/15 catalogs, 377 keys in en)
```

Every claim above was checked on this deployment.

**Channel registered + live** — `GET /api/streams` shows `demo` with the broadcaster's real
feed key and `isLive: true`, populated over the DHT (no manual catalog edit).

## Not done here

* **Signed release APK.** Needs Java + the Android SDK (absent on this box) and a release
  keystore. `brand.mjs` warned that without `signing.json` the APK would use the public
  debug keystore — not shippable. See `docs/white-label.md` "Shipping to production".
* **Public TLS ingress.** The dashboards are on `127.0.0.1`. Expose them with
  `deploy/Caddyfile.example` (or an SSH tunnel), never raw on the WAN.
* **Kernel network tuning.** The logs warn that the swarm UDP buffers are clamped
  (`sysctl -w net.core.rmem_max=2097152`). Fine for a demo; apply
  `deploy/sysctl/install.sh` before real viewer load.

## Secrets

`panel/.env`, `broadcaster/.env`, and everything under `panel/data` / `broadcaster/data`
hold live credentials and keys. All are gitignored. Rotate the admin passwords before any
real use; they were set from a shell here.
